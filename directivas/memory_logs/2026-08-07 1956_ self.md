# Backup Semántico del Chat: Proyecto "Paridad Arancel Dialítico"

## 1. Lógica de Negocio y Reglas Conceptuales del Proyecto

El proyecto tiene como objetivo principal construir una **aplicación web narrativa e interactiva** para presentar el trabajo de investigación "Valor Actual Actuarial en Pacientes bajo Tratamiento Dialítico". La aplicación funcionará como una "historia", dividida en secciones que combinan texto explicativo, visualizaciones dinámicas (diapositivas) y modelos de simulación interactivos.

### Conceptos Clave:
*   **Valor Actual Actuarial de Diálisis (VAAD):** Valor presente único de los flujos de fondos futuros esperados que un financiador transferiría a un prestador por la cobertura de un paciente en diálisis.
*   **Modelos de Riesgos Competitivos / Multiestado de Markov:** Utilizados para corregir el sesgo de sobreestimación de mortalidad del estimador de Kaplan-Meier en pacientes dialíticos (debido a trasplante renal o recuperación de función renal como eventos competidores).
*   **Motor de Costos Polinómico:** Enfoque microeconómico para determinar el valor de la sesión de diálisis, basado en variables como salarios (CCT), USD e IPC.
*   **Regresión Ridge:** Método econométrico para estabilizar la determinación de costos, superando la multicolinealidad estructural que afecta a los Mínimos Cuadrados Ordinarios (MCO).
*   **Precio de Recuperación Actuarial "Hoy":** Metodología final para calcular el valor de sesión necesario para absorber costos futuros y amortizar pérdidas pasadas.

### Arquitectura y Diseño:
*   **Patrón "App Shell":** Header *sticky*, Footer unificado con WhatsApp y enlace "π", y área principal (`<main>`).
*   **Estética:** Diseño *premium*, moderno, corporativo, con soporte completo para modo claro y oscuro (por defecto, `slate-900` de fondo y `teal-500` para acentos).
*   **Textos:** Todos los textos de la interfaz deben cargarse desde un archivo `config.json` para evitar *hardcoding*.
*   **Flujo Narrativo:** Se basa en los 15 capítulos del documento `Trabajo_UNR_Demartis Pablo Nicolás_PARIDAD TÉCNICA ARANCEL DIALÍTICO.docx`, estructurados en 2 partes principales. Cada capítulo se presentará como una "diapositiva" o sección interactiva.
*   **Modelo de Datos:** Las series de datos históricos (IPC, USD, CCT, etc.) se almacenarán en **archivos Excel (.xlsx o .csv)** dentro del proyecto, sin necesidad de una base de datos externa para estos datos.
*   **Despliegue:**
    *   **GitHub:** Repositorio privado para el código fuente.
    *   **Vercel:** Plataforma de despliegue (hosting) Serverless (sin servidor).
    *   **Disponibilidad:** 100% de *Uptime*, no habrá apagados automáticos por inactividad. La página estará siempre disponible, a menos que el usuario la apague manualmente desde Vercel o GitHub.
*   **Autenticación y Seguridad (RBAC):**
    *   **Acceso Restringido:** La aplicación estará bloqueada al público y requerirá un inicio de sesión.
    *   **Proveedor de Autenticación:** Se utilizará **Supabase Auth** para gestionar los usuarios y permisos, **en un proyecto de Supabase completamente aislado** del proyecto "Libro Financiera".
    *   **Roles por Defecto:** Cualquier nuevo usuario que se registre será asignado automáticamente al rol de `"invitado"`. No hay "whitelist" ni "usuarios en suspenso".
    *   **Administradores Iniciales:** Los correos `elcibernico@gmail.com`, `ndemartis@fcecon.unr.edu.ar` y `estudiocontableid@fcecon.unr.edu.ar` (este último se definió inicialmente, pero solo los dos primeros se insertaron en Supabase como administradores por defecto) tendrán acceso total y permisos de administración.
    *   **Panel de Administración:** Un `AdminPanel.jsx` (accesible vía el ícono "π" en el footer) permitirá a los administradores:
        *   Gestionar usuarios (agregar/remover correos).
        *   Asignar permisos granulares.
        *   **Acceso al Panel Admin:** Estrictamente limitado a `ndemartis@fcecon.unr.edu.ar` y `elcibernico@gmail.com`.
    *   **Registro de Actividad:** Se registrará la fecha y hora del último acceso (`last_login`) de cada usuario.
    *   **Granularidad de Permisos:** La matriz de permisos se definirá en 5 niveles jerárquicos: **Parte > Punto > Apartado > Bloque > Desarrollo**. La lógica de herencia será "ascendente implícita": si se otorga acceso a un nivel profundo, los niveles superiores necesarios para la navegación (Parte, Punto, Apartado) serán automáticamente accesibles (solo para lectura/navegación).

### Interacción y Experiencia de Usuario:
*   **Navegación:** La navegación lineal fue eliminada en favor de un Dashboard principal con 5 bloques temáticos (Modelo Actuarial, Quiebre Metodológico, Análisis Econométrico, Parámetros Globales, Bibliografía).
*   **Controles de Navegación:** Los cuadros de "siguiente paso" dentro de las diapositivas 1-4 son clickeables para avanzar la historia.
*   **Consolidación Econométrica:** Los "Puntos" 8 al 11 se unificaron en un solo componente (`ConsolidadoEconometrico.jsx`) con navegación por pestañas (`MCO`, `Ortogonalidad`, `Ridge`, `Validación`).
*   **Gráficos Transversales:** Los gráficos del consolidado econométrico deben permanecer fijos y visibles al cambiar entre pestañas.
*   **Desarrollo Matemático:** Las fórmulas se renderizarán usando LaTeX (MathJax) con botones interactivos para mostrar/ocultar el desarrollo matemático explícito.
*   **Parámetros Globales:** Un `GlobalContext` (React Context) se encargará de centralizar y persistir los parámetros de simulación a lo largo de toda la aplicación.

## 2. Bitácora de Errores Técnicos y Soluciones

1.  **Error:** `pandoc` no reconocido al intentar leer `.docx`.
    *   **Solución:** No se solucionó directamente la instalación de `pandoc`. En su lugar, el agente leyó el archivo `.docx` como texto plano (o convirtió a `.txt`) para extraer el hilo narrativo.
2.  **Error:** Problemas de compilación de Vite/TailwindCSS:
    *   `[postcss] It looks like you're trying to use tailwindcss directly as a PostCSS plugin.`
    *   `Error: Cannot apply unknown utility class bg-slate-900.`
    *   **Solución:** Se corrigió la configuración de TailwindCSS. Se actualizó `postcss.config.js` para usar `@tailwindcss/postcss` y se aseguró la correcta importación de las directivas de Tailwind en `src/index.css`. Se ejecutó `npm install` y `npm run build` con éxito.
3.  **Error:** `Failed to resolve import "@supabase/supabase-js"`. La librería de Supabase no se encontraba.
    *   **Solución:** Se añadió manualmente `@supabase/supabase-js` a las dependencias en `package.json`, se ejecutó `npm install` y se reinició el servidor de desarrollo de Vite.
4.  **Error:** `npx : No se puede cargar el archivo C:\Program Files\nodejs\npx.ps1 porque la ejecución de scripts está deshabilitada...` al intentar iniciar el servidor de desarrollo.
    *   **Solución:** Se utilizó `cmd /c "npm run dev"` para ejecutar el comando `npm run dev` directamente a través del *command prompt* de Windows, saltando la política de ejecución de scripts de PowerShell.
5.  **Error:** Supabase SQL syntax error `on conflict (email) do modify;`.
    *   **Solución:** Se corrigió el script `supabase_schema.sql` cambiando `do modify` (sintaxis no válida en PostgreSQL) por `do nothing` (o `do update set ...`) para la cláusula `ON CONFLICT`.
6.  **Error:** `Error de HTTP en la API de Gemini: 429 - RESOURCE_EXHAUSTED` al intentar generar el backup semántico del chat (cuota excedida).
    *   **Solución:** Se modificó el script `backup_chats.py` para truncar el historial del chat a un máximo de 400.000 caracteres (conservando el inicio y el final) antes de enviarlo a la API de Gemini, para asegurar que se mantenga dentro de los límites de tokens por minuto del Free Tier.
